> 老版本框架分析见 `03_老版本框架参考.md`。
> 日期：2026-10-07　状态：需求已确认，待进入阶段 2

## 1. 模块定位

- 名称：`application/chassis.c` / `application/chassis.h`（沿用老版本文件名与函数结构）
- 输入：遥控器（摇杆 ch2/ch3、拨杆 s[0]/s[1]、键盘 W/S/A/D/F/R）、
        yaw 云台电机反馈（CAN1 0x205，GM6020）、四路底盘电机速度反馈（CAN1 0x201~0x204）
- 输出：CAN1 0x200 四路电流指令（C620 电调，-16384~16384）
- 周期：2ms（chassis_task，osDelay(2)）
- 不负责：云台控制、发射机构、裁判系统（本期仅留接口占位）

## 2. 需求清单（MoSCoW）

### Must-have
1. chassis_task 2ms 周期任务，在 freertos.c 的 RTOS_THREADS 块注册
2. 麦轮（全向轮）运动学解算 —— **修正老版本 bug**：
   - 老版 pwm3/pwm4 复制了 pwm1/pwm2（四轮实际只有两个自由度）
   - 老版 revolve 模式平移矩阵被注释（vy1/vx1 恒 0）
   - 新版必须四轮完整解算：平移 (vx, vy) + 旋转 (ω) 三个自由度
   - **解算公式采用 StandardRobotpp 标准逆运动学**（详见 `03_老版本框架参考.md` §6.2）：
     `set[i] = (√2/2·(vx∓vy) ∓ L·wz) / R × ratio × direction`，
     每轮 `direction(±1)` 参数化，接线确定后只改参数宏
   - FOLLOW 模式采用标准做法（§6.3）：平移速度经 yaw_delta 旋转矩阵变换到云台系，
     旋转分量用 follow PID 把 yaw_delta 归零（替代老版"速度环输出直接加轮速"的近似做法）
3. 双模式：
   - `CHASSIS_VECTOR_FOLLOW_GIMBAL_YAW` 底盘跟随云台：
     yaw 电机编码器与中值差 → follow 角度环(0.1/0/0 增量式) → follow 速度环(25/3.5/0)
     → 修正量加到四轮目标速度
   - `CHASSIS_VECTOR_revolve` 小陀螺：摇杆平移（低通 0.8/0.2，×5 增益）
     + 固定自旋速度 v_revolve(5000)
4. 四轮速度环 PID（参数 5/0.2/1，位置式，max_out 12000，max_iout 100）
5. CAN 发送：`CAN_cmd_chassis(左上, 右上, 左下, 右下)`（复用现有 bsp_can）
6. 安全保护（等价移植老版）：
   - 遥控器掉线 → 四轮发零
   - 右拨杆 DOWN（s[1]==0x02，键盘云台模式）→ 底盘锁死发零
   - 目标速度限幅 ±MaxGivenSpeed(7500)
   - Ramp 斜坡函数（死区 66，步进 6/周期）
7. VOFA 调试变量：底盘模式、四轮目标/实际速度、解算中间量、跟随修正量

### Should-have
8. 遥控器掉线检测（简化版：记录 rc_ctrl 更新时间戳，超时判掉线；
   不移植完整 detect_task 框架）
9. yaw 电机中值上电自动标定（开机静止读编码器取均值，替代硬编码 A6020_M=1300）
10. 功率限制接口占位：`get_chassis_power_and_buffer()` 留空壳，
    本期 `Power_Buffer = 50.0f` 写死禁用，注释标注 RMUL 参赛前接裁判系统
11. 键盘 F/R 切换模式（s[1]==DOWN 时生效）

### Could-have
12. 超级电容功率补偿
13. GPS/自瞄底盘指令（`Chassis_Mode == 0x0A` → revolve）
14. 完整 detect_task TOE 框架移植

### Won't-have（本期明确不做）
- 裁判系统完整协议栈（referee.c）
- navigation 导航模块
- 云台/发射机构改造（gimbal 继续跑正弦测试，互不干扰）

## 3. 开发约束（用户确认）

1. **框架沿用老版本**：文件名 `chassis.c/h`、函数名 `chassis_task / chassis_set_mode /
   chassis_set_control / chassis_set_v / ChassisController / ChassisPidCtr / Ramp_function`、
   结构体名 `RemoteParam_Struct / ChassisParam_Struct / chassis_mode_e` 全部保持一致。
2. **接线符号先用老版约定**，实车再调。实现时：
   - 所有依赖接线方向/轮序的代码处，用统一标记注释：
     `// TODO-接线标定: <依赖什么方向、现象是什么、怎么改>`
   - **参照 StandardRobotpp 的参数化设计**：chassis.h 顶部集中定义
     「轮序/方向参数区」——每轮 direction(±1)、CAN ID、减速比、轮半径、
     轮心到中心距全部宏参数化，接线确定后**只改参数区，不改解算主体**；
   - 解算公式注释中写明：某轮反转→该轮 direction 取反；轮序错位→交换对应宏。
3. 编码 UTF-8 带 BOM（工程硬性约定）；代码只写在 USER CODE 块内。
4. 每完成一个最小可验证单元（MVU）交付一次，等验证结果再继续。
