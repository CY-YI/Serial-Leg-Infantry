# 1. 先建立一个画面：比赛里的电是怎么被管的

## 1.1 一条规则

比赛规定：**机器人底盘的功率不能超过一个上限**（步兵大约 45W~100W，随等级变化）。

超过会怎样？不是直接判负，而是**扣"缓冲能量"**；缓冲能量扣光了还在超，就**扣血**。

所以整场比赛，机械上你要快，电气上你要"巧"——**把功率用满，但不越界**。

## 1.2 谁在盯着你

```
电池 → 电源管理模块 → 底盘电机（4 个）
            ↑
       裁判系统在这里测量
```

电源管理模块（PM）在电池和底盘之间，它测的是**底盘这一路**的电压、电流、功率。
裁判系统通过串口把这些数字发回主控，主控据此判断"我现在超没超"。

注意：**云台、发射机构的电不算在底盘功率里**，它们有各自的限制（热量）。

## 1.3 三个关键名词

| 名词 | 通俗解释 | 单位 |
|------|---------|------|
| 功率上限 | 你"每小时能花的钱"的上限 | W（瓦） |
| 缓冲能量 | 你的"信用卡额度"，超支时先刷它 | J（焦耳） |
| 扣血 | 额度刷爆了，开始扣你血量 | HP |

记住这个比喻，后面所有东西都能对上：

> **功率 = 花钱速度，缓冲能量 = 信用卡额度，扣血 = 逾期罚款。**

# 2. 物理基础：功率、能量、为什么两者要分开

## 2.1 三个词的关系

```
功率 P  = 单位时间内消耗的能量     单位：瓦 W = 焦耳/秒 J/s
能量 E  = 功率对时间的累积         单位：焦耳 J
                          E = P × t（功率恒定时）
```

举个好懂的例子：

- 一个 100W 的灯泡，开 1 秒，消耗 100J
- 一个 50W 的灯泡，开 2 秒，也是 100J

**同样的能量，功率大就时间短。** 这就是为什么比赛既限功率、又给缓冲。

## 2.2 为什么不能只看功率

如果你的功率"瞬间"冲到 200W，但只持续 1 毫秒：

- 多出来的能量 = (200-80)W × 0.001s = 0.12J
- 缓冲有 60J，根本无感

但如果你持续 1 秒：

- 多出来 = 120W × 1s = 120J
- 60J 的缓冲直接被刷爆，然后扣血

**所以真正伤你的是"持续超功率"，不是"瞬时尖峰"。** 这也是为什么缓冲能量这个设计是合理的。

## 2.3 单位换算（常用）

```
1 W = 1 J/s
1 Wh = 3600 J
60 J 的缓冲 ≈ 一个 60W 的电器工作 1 秒的能量
```

# 3. 缓冲能量（buffer）到底是什么

## 3.1 官方定义（简化版）

裁判系统给每台机器人一个**缓冲能量池**，满值是 **60J**。

规则机制：

1. 你每秒消耗的功率 ≤ 功率上限 → **buffer 不动**（或者缓慢回充）
2. 你每秒消耗的功率 > 功率上限 → **超出部分从 buffer 里扣**
3. buffer 扣到 0 之后还超 → **开始扣血**

## 3.2 "吃 buffer"到底是怎么吃的

用数字说最清楚。假设：

- 功率上限 = 80W
- buffer = 60J（满的）

### 情况 A：你稳定跑 80W

```
超出量 = 80 - 80 = 0 W
buffer 完全不掉
```

### 情况 B：你稳定跑 120W

```
超出量 = 120 - 80 = 40 W
即每秒吃掉 40 J
60J ÷ 40J/s = 1.5 秒后 buffer 归零
```

**1.5 秒后开始扣血。**

### 情况 C：你只超一点点，跑 90W

```
超出量 = 90 - 80 = 10 W = 10 J/s
60J ÷ 10J/s = 6 秒
```

**能撑 6 秒。**

### 情况 D：143W

```
超出量 = 63 W
60 ÷ 63 ≈ 0.95 秒
```

不到 1 秒就爆。

## 3.3 一张表看完全部

| 实际功率 | 超出量 | 能撑多久（60J 满） |
|---------|--------|------------------|
| 80W（=上限） | 0 | 无限 |
| 90W | 10J/s | 6 秒 |
| 100W | 20J/s | 3 秒 |
| 120W | 40J/s | 1.5 秒 |
| 140W | 60J/s | 1 秒 |
| 200W | 120J/s | 0.5 秒 |

## 3.4 关键结论

> **缓冲能量就是你的"爆发时间"。**
> 平时攒着，需要冲刺/顶人的时候一口气用掉。

## 3.5 为什么不能一直贴着上限跑

三个原因：

1. **测量有延迟**：裁判 10Hz 才报一次，等它报回来你已经超了 100ms
2. **模型有误差**：你算的 79W 可能实际是 85W
3. **buffer 需要留余量**：万一要应急加速，得有存货

所以实际策略通常是：**稳态跑在 40~50J 的 buffer 上**（不是 60，留一点缓冲），需要时再爆发。

# 4. 电机功率模型：电都花在哪了

这是整个功率控制的核心。**如果你只记住一件事，就记这一节。**

## 4.1 电机的电去哪了

电机吃进去的电（P_in），变成了：

```
P_in = 机械输出功率 + 各种损耗
```

损耗有四种：

| 损耗 | 是什么 | 和什么有关 |
|------|--------|-----------|
| 铜损 | 线圈电阻发热 | 电流平方（I²R） |
| 铁损 | 磁滞、涡流 | 转速相关 |
| 机械损耗 | 减速箱摩擦、轴承阻尼 | 转速相关 |
| 静态损耗 | 控制器待机、传感器 | 常量 |

## 4.2 机械功率（唯一"有用"的部分）

```
P_机械 = τ × ω

τ = 力矩（牛·米 N·m）
ω = 角速度（弧度/秒 rad/s）
```

注意单位：**转速要先从 RPM 换成 rad/s**：

```
ω(rad/s) = RPM × 2π / 60
例：3000 RPM → 3000 × 6.283 / 60 ≈ 314 rad/s
```

**这里有个极其重要的直觉**：

> 同样的力矩，转速越高，功率越大。
> 力矩是"力气"，功率是"力气 × 速度"。

这解释了一个现象：**低速顶墙时电流很大但功率不一定高；高速冲刺时电流稍大功率就爆表。**

## 4.3 把损耗加进来：完整的经验模型

经过大量实测，社区公认的模型是（单个电机）：

```
P_i = τ_i × ω_i  +  k1 × |ω_i|  +  k2 × τ_i²  +  k3/n
      └──机械──┘    └─转速损耗─┘  └─铜损─┘   └静态┘
```

四个部分对应：

| 项 | 含义 | 为什么是这个形式 |
|----|------|-----------------|
| `τ·ω` | 真正做功 | 物理定义 |
| `k1·\|ω\|` | 铁损 + 机械阻尼 | 转速越高损耗越大 |
| `k2·τ²` | 铜损（I²R） | 力矩正比于电流，所以是平方 |
| `k3/n` | 静态损耗（每个电机分摊） | 控制器待机、传感器等 |

四轮加起来：

```
P_总 = Σ(τ_i × ω_i) + k1 × Σ|ω_i| + k2 × Σ(τ_i²) + k3
```

## 4.4 三个系数分别代表什么

| 系数 | 代表 | 港科大实测值 |
|------|------|-------------|
| `k1` | 转速相关损耗 | 0.22 |
| `k2` | 铜损系数 | 1.2 |
| `k3` | 整车静态损耗（W） | 2.78 |

> ⚠️ 这三个数是**对某台特定车**拟合出来的，换车、换电机、换减速箱都要重新标。
> 但先用它们跑起来，比"完全没模型"强得多。

## 4.5 力矩 τ 怎么从"电流指令"得到

电调协议里，你发的是一个整数（比如 -16384~16384），不是安培，也不是牛·米。

换算链：

```
电流指令（整数）
   ↓ 除以量程，乘最大电流
实际电流 I（A）
   ↓ 乘力矩常数 Kt
力矩 τ（N·m）
```

在代码里通常合并成一个系数：

```
k0 = Kt × (最大电流 / 最大指令值)
τ = 电流指令 × k0
```

港科大代码里的写法就是：

```c
const float k0 = torqueConst * currentLimit / outputLimit;
τ_i = pidOutput * k0;
```

## 4.6 一个算得出来的例子

假设（数字是为了好算，不是真实标定）：

- 某个轮：力矩 τ = 0.15 N·m，转速 ω = 300 rad/s，k1=0.22，k2=1.2，k3=2.78

```
机械功率 = 0.15 × 300 = 45 W
转速损耗 = 0.22 × 300 = 66 W   ← 注意！这一项很大
铜损     = 1.2 × 0.15² = 0.027 W
静态     = 2.78/4 ≈ 0.7 W
─────────────────────────────
单轮 ≈ 111.7 W
四轮 ≈ 447 W
```

**看到没？45W 的机械功率，实际要从电池拿 112W。** 这就是为什么"看着功率不大"其实已经超了。

> 注：这个例子里 k1 项偏大，说明 k1 的数值和 ω 的单位强相关。
> **实际标定时必须用自己的数据拟合**，不能照搬别人的 k1/k2/k3。

## 4.7 为什么模型里要有 τ² 项（一个容易忽略的场景）

考虑"顶墙"：轮子被挡住，转速 ω = 0，但你还在给大电流。

```
机械功率 = τ × 0 = 0
```

如果模型只有 τ·ω 这一项，会算出**功率为 0**——大错特错！

实际此时电流很大，铜损 `k2·τ²` 才是主要消耗。所以：

> **堵转/顶墙时，功率几乎全部来自 τ² 项。这一项不能省。**

# 5. 从"预测功率"到"限制输出"

## 5.1 为什么不能用裁判的数据直接控

| | 底盘控制环 | 裁判系统数据 |
|---|---|---|
| 频率 | 2ms（500Hz） | 约 100ms（10Hz） |
| 延迟 | 极小 | 50~150ms |

**裁判报回来时，你已经超功率 100ms 了。**

所以结构必须是**双环**：

```
慢环（10Hz，用裁判数据）  →  决定"这一段时间的功率上限是多少"
        ↓
快环（500Hz，用电机模型）  →  决定"这一拍每个轮子给多少电流"
```

**这就解释了为什么必须有模型**：快环等不到裁判数据，只能自己算。

## 5.2 快环的完整流程

```
① 底盘解算 + PID  →  得到四个轮子的"期望电流指令"
        ↓
② 用模型算：如果按这个指令发出去，总功率会是多少？（P_cmd）
        ↓
③ 判断：P_cmd ≤ P_max 吗？
        ├─ 是 → 原样输出，什么都不做
        └─ 否 → 进入"功率再分配"
                  ↓
④ 把 P_max 分配给四个轮子（不是简单平分！）
                  ↓
⑤ 每个轮子按分到的功率，反解出"最大能给的力矩"
                  ↓
⑥ 输出新的电流指令
```

## 5.3 第④步最关键：为什么不能简单平分/等比缩放

假设四个轮子原本要的功率是 [40W, 40W, 10W, 10W]，总和 100W，但上限只有 60W。

### 做法 A：等比缩放（乘 0.6）

```
[24W, 24W, 6W, 6W]  → 总和 60W ✔
```

看起来没问题？但实际会出大事：

> **四个轮子的功率需求不一样，是因为它们承担的负载不一样。**
> 等比缩放会让"本来不需要那么多功率的轮子"也按比例降，
> 而"需要功率的轮子"降得不够——结果就是**车走不直、原地打转**。

这就是很多队"一开功率控制就走不了直线"的原因。

### 做法 B：按"误差"分配

```
哪个轮子的实际转速离目标最远，就多给它功率
```

```
分配比例 = |目标转速 - 实际转速| / 四个轮子误差之和
```

好处：能快速纠正偏差，不影响运动学。
坏处：**当四个轮子误差都很小（比如在坡上停着）时，分母接近 0，分配会剧烈抖动。**

### 做法 C：混合（港科大的做法，推荐）

引入一个"置信度" K（0~1）：

```
总误差很大  → K = 1  → 完全按误差分配
总误差很小  → K = 0  → 完全按功率比例分配
中间        → 线性过渡
```

最终权重：

```
权重_i = K × (误差_i / 总误差) + (1-K) × (功率_i / 总功率)
```

**这样一个公式同时解决了"走不直"和"坡上抖动"两个问题。**

## 5.4 第⑤步：解一元二次方程

现在每个轮子分到了功率 `P_i`，要求出"给它多少力矩"。

从模型出发：

```
P_i = τ×ω + k1|ω| + k2τ² + k3/4
```

移项整理成关于 τ 的一元二次方程：

```
k2·τ² + ω·τ + (k1|ω| + k3/4 - P_i) = 0

对应 ax² + bx + c = 0：
a = k2
b = ω
c = k1|ω| + k3/4 - P_i
```

求根公式：

```
τ = (-ω ± √(ω² - 4·k2·c)) / (2·k2)
```

判别式 `Δ = ω² - 4·k2·c` 有三种情况：

### 情况 1：Δ > 0（两个实数解）

一个解对应"大电流"，一个对应"小电流"。

> **选和原 PID 输出同号的那个**，保证方向不变。
> 原输出为正 → 取 `(-ω + √Δ)/(2k2)`
> 原输出为负 → 取 `(-ω - √Δ)/(2k2)`

### 情况 2：Δ = 0（重根）

```
τ = -ω / (2·k2)
```

### 情况 3：Δ < 0（无实数解）

物理意义：**在当前转速下，无论给多大力矩都到不了这个功率**。
（比如分到的功率太小，还不够抵消损耗）

此时取近似解：

```
τ = -ω / (2·k2)
```

最后再限幅到原来的 PID 输出范围（不能因为功率控制反而给出更大的电流）。

## 5.5 关于"负功率"

当电机被反拖（比如下坡、刹车）时，τ 和 ω 反向，`τ·ω < 0`，意味着**电机在发电**。

港科大的处理是：**负功率直接放行，不参与限幅**。

原因：实测影响很小，而且硬要处理会让方程出现虚数解。
但注意：**如果你加了超级电容，这块就是收益点**（能量可以回收）。

# 6. 能量环：为什么还要再加一层

## 6.1 功率环有什么问题

功率环（第 5 节那一套）已经能限制功率了，但它有两个天生的缺陷：

1. **模型不准**：k1/k2/k3 是拟合出来的，有误差
2. **有延迟**：从计算到电机真正出力，中间有电调响应时间

结果就是：**你以为自己在 80W，实际可能是 75W 或 85W。**

## 6.2 能量环干什么

它不看"瞬时功率"，而看**缓冲能量这个"存量"**。

打个比方：

> **功率环**像一个严格的会计，每一笔都算得死死的。
> **能量环**像你的妈妈看你的银行卡余额：
> "余额还有 50 块？那今天可以多吃点。"
> "余额只剩 5 块了？省着点花。"

## 6.3 具体做法

用 PD 控制器，反馈量是缓冲能量：

```
e = √(目标能量) - √(当前能量)

P_max = P_base - Kp × e - Kd × (e - e_prev) / dt
```

解释每一项：

| 符号 | 含义 |
|------|------|
| `E_target` | 你希望 buffer 稳定在多少（比如 45J） |
| `E_current` | 裁判报回来的实际 buffer |
| `e` | 偏差（正数=能量不够，要收敛） |
| `P_base` | 基础功率上限（裁判给的，比如 80W） |
| `Kp` | 比例系数：偏差越大，降得越狠 |
| `Kd` | 微分系数：抑制震荡 |
| `P_max` | 最终交给功率环的上限 |

**工作过程**：

```
buffer 很高（55J） → e 为负 → P_max 变大 → 允许你多用点功率
buffer 很低（20J） → e 为正 → P_max 变小 → 强制你省电
```

## 6.4 为什么要开根号

两个原因：

1. **电容的物理特性**：电容储能 `E = ½CV²`，所以 `V ∝ √E`。开根号后，控制量更接近"电压"这个线性量，响应更均匀。
2. **数值特性**：能量高时和低时，同样 1J 的变化，意义差别很大。开根号能压缩高端的灵敏度。

对裁判的 buffer（不是真电容）而言，开根号更多是"沿用社区实践"，效果是被验证过的。

## 6.5 能量环和功率环的分工

| | 功率环 | 能量环 |
|---|--------|--------|
| 频率 | 500Hz（跟控制环） | 10Hz（跟裁判数据） |
| 输入 | 电机反馈 + 模型 | 缓冲能量 |
| 输出 | 每个轮子的电流 | 功率上限 P_max |
| 作用 | 保证这一拍不超 | 保证长期不爆 |

**慢环调上限，快环管执行。**

# 7. 老方案为什么不行

## 7.1 老代码长什么样

```c
if (Power_Buffer < 50.0f)
{
    LimtOutValue = Power_Buffer * Power_Buffer * 6.0f;   // 功率限制值
    // 然后四路输出按 LimtOutValue / Σ|输出| 等比缩放
}
```

翻译成人话：**缓冲能量低于 50 时，按它的平方乘 6，得到一个"电流总和"的上限，然后四路等比缩小。**

## 7.2 五个问题

### 问题 1：量纲是错的

buffer 的单位是**焦耳**。焦耳平方乘个系数，得到的是"电流之和"？

```
J² × 常数 ≠ A
```

这不是从物理推出来的，只是当年"buffer 越低越狠地限"的一条经验曲线。

### 问题 2：完全没用实测功率

老代码里：

```c
get_chassis_power_and_buffer(&Power, &Power_Buffer);
```

`Power` 读出来了，**然后丢了**，只用了 buffer。

等于放弃了唯一一个真实的测量量。

### 问题 3：完全不区分转速

第 4 节说过：功率 = 力矩 × 转速。

老公式对转速一无所知，所以：

- **高速冲刺时**：严重超功率（被扣 buffer）
- **低速爬坡时**：过度限流（明明还有余量，车却爬不动）

### 问题 4：等比缩放会导致走不直

见 5.3 节。

### 问题 5：系数是 2019 年的

`×6.0` 和阈值 `50` 是给当年规则的。现在规则变了，这组数字没有任何依据。

## 7.3 一句话总结

> 老方案不是"不够好"，而是**它根本不知道功率是多少**。

# 8. 超级电容：它到底帮你解决什么

## 8.1 它和电池有什么区别

| | 电池 | 超级电容 |
|---|------|---------|
| 储能密度 | 高（能撑一整场） | 低（只够几十秒） |
| 放电能力 | 中等 | **极强**（瞬间几十安培） |
| 充放电速度 | 慢 | **极快**（秒级） |
| 成本 | 低 | 高 |

一句话：**电池是"油箱"，超电是"加速器"。**

## 8.2 为什么说它是"合法的作弊"

关键点：**裁判系统只测电池侧的底盘功率，超电放出来的电不算。**

```
电池 → 电源管理模块 → 底盘
            ↑
      裁判在这里测（只测电池这一路）

超电 → DCDC → 并入底盘母线（不经过测量点）
```

所以：

```
实际给电机的功率 = 裁判测到的功率 + 超电放出的功率
```

你可以让裁判看到 80W，但电机实际拿到 300W。

## 8.3 超电带来的控制变化

有超电后，功率上限就变成：

```
P_max = 裁判功率上限 + 超电允许放出的功率
```

而能量环的反馈量，从"裁判 buffer"换成"超电剩余 SOC"。

港科大的接口设计值得学：

```c
setMaxPowerConfigured(float maxPower);   // 上层随时改 P_max
```

**功率模块不关心这个数从哪来**——没超电时来自裁判，有超电时来自能量策略。

## 8.4 我们暂时没有超电，怎么办

完全不影响第一阶段：

- 没有超电 → `P_max` 就是裁判给的值
- 没有裁判 → `P_max` 写死一个保守值（比如 60W）
- 功率环代码**一行都不用改**

**这就是为什么我建议把 `P_max` 设计成"外部可写的变量"。**

# 10. 我们的实施路线

| 阶段 | 做什么 | 依赖 | 验收标准 |
|------|--------|------|---------|

# 11. 参数标定手册

## 11.1 先标 k3（最简单）

`k3` 是整车静态损耗：电机不转、不给电流时，底盘这一路还在消耗的功率。

**步骤**：

1. 上电，底盘电机全部给 0 电流（LOCK 模式即可）
2. 读裁判系统的 `chassis_power`
3. 取 10 秒平均值 → 就是 `k3`

典型值：2~5W（控制器、传感器、指示灯等）。

## 11.2 再标 k1 和 k2

需要真实功率测量，方法：给定一系列 (电流, 转速) 组合，测功率，最小二乘拟合。

**步骤**：

1. 固定一个转速（比如用另一个电机拖动，或在坡上让轮子匀速转）
2. 给一系列电流指令：10%、20%、30%...
3. 每个点记录：电流 I、转速 ω、实测功率 P
4. 用这些点拟合 `P - τ·ω = k1·|ω| + k2·τ² + k3`

**注意事项（来自社区经验）**：

- ❌ **不要空载拟合**——空载时几乎不耗功率，拟合出来全是噪声
- ❌ 不要用台架小电源做大电流标定（会限流，数据失真）
- ✅ 用电池供电、带负载（或者有惯性的转鼓）

## 11.3 或者偷懒：用 RLS 在线自标定

如果不想手动拟合，可以在运行时用**递归最小二乘（RLS）**自动更新 k1/k2：

- 前提：必须有真实的功率反馈（裁判系统或超电）
- 原理：每来一组新数据，就微调一次参数，让它越来越准
- 港科大就是这么做的，参数初值给 0.22 / 1.2，跑一会儿就收敛了

**我们现在没有裁判，所以这条暂时用不了**，只能先借默认值。

## 11.4 力矩常数 Kt 和换算系数 k0

```
k0 = Kt × (最大电流 / 最大指令值)
```

- `Kt`：查电机手册（M3508 约 0.0156 N·m/A，转子侧）
- `最大电流`：电调量程（C620 约 20A）
- `最大指令值`：16384

# 12. 常见问题 FAQ

## Q1：为什么一开功率控制，车就走不直？

因为用了"等比缩放"分配。四个轮子负载不同，等比缩放会破坏运动学关系。

**解决**：改成按误差分配，或者用混合策略（见 5.3）。

## Q2：为什么 buffer 一直在掉，明明没超功率？

可能是：

1. 模型算低了（实际比你以为的高）
2. 底盘上有其他负载（灯、传感器）没算进去
3. 功率上限读错了（等级变了）

**排查**：直接看裁判报的 `chassis_power` 和你模型算的差多少。

## Q3：顶墙的时候为什么会突然掉血？

因为顶墙时转速为 0，如果模型里没有 `k2·τ²` 项，会算出"功率为 0"，于是完全不做限制，实际功率却很高。

**解决**：模型必须有 τ² 项（见 4.7）。

## Q4：为什么刹车/下坡时功率会变负？

电机被反拖，变成了发电机，能量往母线灌。

- 没超电：这部分能量由电池/电源管理模块吸收，一般不处理
- 有超电：可以回收，是收益点

## Q5：裁判 10Hz 的数据能做闭环吗？

能，但只能做**慢环**（能量环、参数自适应）。2ms 的快环必须用模型。

## Q6：k1/k2/k3 能直接抄别人的吗？

**可以作为初值，但不能当最终值。** 换车、换电机、换减速箱、换轮子都要重标。

# 13. 术语表

| 术语 | 解释 |
|------|------|
| **buffer / 缓冲能量** | 裁判给的 60J 额度，超功率时先扣它 |
| **功率上限** | 底盘允许的最大功率，随等级变化 |
| **功率环** | 用电机模型预测 + 限制输出的快速环（500Hz） |
| **能量环** | 用 buffer 反馈调功率上限的慢速环（10Hz） |
| **机械功率** | τ × ω，真正推动车做功的功率 |
| **铜损** | 电流在线圈电阻上的发热，正比于电流平方 |
| **铁损** | 磁场交变造成的损耗，与转速相关 |
| **RLS** | 递归最小二乘，在线自动拟合参数 |
| **二次求解** | 由功率反解力矩，解一元二次方程 |
| **堵转 / 顶墙** | 轮子转不动但还在给电流 |
| **回馈 / 反电动势** | 电机被反拖时发电，能量回流母线 |
| **超电 / 超级电容** | 高功率密度的储能器件，可瞬时大电流放电 |
| **DCDC** | 直流变换器，控制超电的充放电 |
